WORKSPACE Doctrine
1. Purpose of the WORKSPACE
The WORKSPACE is the archive’s universal mechanism for recording changes, adjustments, interpretations, and developments across all entries. It functions as the historical memory of the archive, preserving the evolution of each document in a transparent, chronological, and collaborative manner. Every entry in the archive must include a WORKSPACE section.
2. Universal Rules
The following rules apply to all WORKSPACEs, regardless of domain:

  • The WORKSPACE is chronological.
  • The WORKSPACE is append‑only.
  • No entry may be deleted, overwritten, or retroactively edited.
  • All changes must be recorded using the required format.
  • The WORKSPACE must not contain definitions, doctrine, identity information, or tags.
  • The WORKSPACE must not be merged with the identity block or definition block.
  • The WORKSPACE is the only location where revisions may be documented.

3. Required Format
Each WORKSPACE entry must follow this exact structure:
Date — Participant(s) — Description of Change
Examples:

  • 27 April 2026 — Zachar — Added initial definition block.
  • 27 April 2026 — Copilot — Revised grammatical category description.
  • 28 April 2026 — Copilot, Zachar — Adjusted semantic notes after discussion.

The format must be used consistently across all domains.
4. Content Appropriate for the WORKSPACE
The WORKSPACE must record:

  • additions
  • corrections
  • clarifications
  • expansions
  • structural adjustments
  • interpretive notes
  • collaborative decisions
  • meta‑reflections directly tied to a change

The WORKSPACE is the only sanctioned location for documenting the evolution of an entry.


5. Content Not Permitted in the WORKSPACE
The WORKSPACE must not contain:

  • definitions
  • doctrine
  • identity block information
  • tags
  • narrative content
  • commentary unrelated to a specific change
  • speculative or creative writing not tied to revision

All non‑revision content must remain in the main body of the entry.


6. Relationship to Other Doctrines
The WORKSPACE Doctrine interacts with the following doctrines:

  • Authorship Doctrine — because authorship is recorded in WORKSPACE entries.
  • Tagging Doctrine — because tag adjustments must be logged in the WORKSPACE.
  • Lexicon Entry Doctrine — because Disfodish entries rely on WORKSPACE evolution for semantic drift and interpretive history.

These doctrines must be referenced when relevant.
